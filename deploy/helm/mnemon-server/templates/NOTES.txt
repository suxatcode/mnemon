Issue a user (no restart required). In-pod `MNEMON_DATA_DIR=/data` and, when using Postgres, `MNEMON_DATABASE_URL` already match `serve` — omit `--data-dir` unless you overrode the store path.

  kubectl exec -it deploy/{{ include "mnemon-server.fullname" . }} -- \
    mnemon-server user issue \
      --principal alice@team --role user \
      --server {{ if .Values.server.tls.enabled }}{{ include "mnemon-server.fullname" . }}:{{ .Values.service.port }}{{ else }}http://{{ include "mnemon-server.fullname" . }}:{{ .Values.service.port }}{{ end }} \
      --jwt-key /config/{{ .Values.server.jwtKeyKey }} \
      {{- if and .Values.server.tls.enabled (include "mnemon-server.mountCA" .) }}
      --ca-file /config/ca.crt \
      --server-name {{ include "mnemon-server.fullname" . }} \
      {{- end }}
      --out -

Then on the client: mnemon auth login --default invite.json

Production AWS: use values-aws.yaml (or values-rds.yaml) with postgresql.enabled=false, a DSN secret, and optionally server.existingSecret for an HS256 key from External Secrets / AWS Secrets Manager. Users live in Postgres (`principals` and `issued_tokens` tables). Adding a user is an INSERT plus JWT issue; no pod restart.
