Then on the client: mnemon auth login --default invite.json

From a workstation that can reach Postgres (no kubectl), copy `jwt.key` and the DSN:

  mnemon-server user issue \
    --database-url "$MNEMON_DATABASE_URL" \
    --jwt-key ./jwt.key \
    --principal alice@team --role user \
    --server {{ $target }} \
    --out invite.json

Revoke every token for a principal (takes effect immediately):

  kubectl exec deploy/{{ include "mnemon-server.fullname" . }} -- \
    mnemon-server user revoke --principal bob@team

Postgres is always external. Production: values-aws.yaml (Ingress + cert-manager, HTTP pods), values-istio.yaml (mesh Gateway, HTTP pods), or values-rds.yaml (DSN only). Users live in Postgres (`principals` and `issued_tokens` tables). Adding a user is an INSERT plus JWT issue; no pod restart. Rotating `jwt.key` invalidates every existing token — re-issue after a key change.
